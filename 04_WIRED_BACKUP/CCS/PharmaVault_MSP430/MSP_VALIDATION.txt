PHARMAVAULT WEEKLY REFILL - MSP430 VALIDATION
2026-11-13

NATIVE TARGET BUILD: PASS
TI MSP430 compiler 21.6.2.LTS, C99, MSP430F5529 small code/data model.
main.c, dht11.c and rc522.c compiled and linked without diagnostics.
Included .out/.hex were generated from this release's source and their bytes
match the native build artifacts.
Linker allocation: RAM 1500/8192 bytes;
main FLASH 17163/48000 bytes.

SOURCE-BACKED HOST TESTS: PASS
Actual receive_frame/display_ui functions tested with CRC-framed WEEK replies.
All 32 combinations of day 0..7 and SETUP/ACTIVE/REFILL/CLOCK display the
expected text, fit the 16-column LCD and finish only the matching TAG once.
Wrong sequence, command kind, checksum, field count, day, invalid status,
duplicate and unawaited responses cannot change the card information.
Routine ESP UI cannot overwrite weekly status during its eight-second hold;
MOTOR_FAULT can interrupt. Hold rollover and day-zero wording pass.
Legacy REFILL parsing/display and error cases remain covered.

Existing actual-source reader/queue regressions also passed: one TAG/no LOGREQ,
held-card suppression, confirmed clean removal, replacement cards, ambiguous
RF failures, queue overflow, expired taps, reader failure and tick rollover.
These reader events are informational to the weekly ESP; NFC is not a daily
dispensing gate and never confirms weekly refill.
Host warnings are MSVC CRT deprecation warnings for bounded strcpy calls;
no native TI compiler diagnostics occurred.

UNCHANGED COMPONENTS
DHT11, RC522, protocol, thermistor configuration and linker files are byte
identical to the IRTestMode package. The existing main.c function bodies for
clocks, ADC, thermistor conversion, sensor sampling, timers, UART, card reader,
LCD hardware and ISRs also compare unchanged. Only the weekly response/UI
comments and startup version banner differ from those original functions.
Existing hardware pins and LPM0 behavior are retained.

LIMITS
CCS GUI import, flashing, physical NFC reads, LCD contrast and sensor operation
were not exercised here. Weekly status is provided by the ESP32, does not
measure remaining stock and does not verify actual medication delivery.
