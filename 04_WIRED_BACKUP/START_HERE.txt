PHARMAVAULT - REPEATABLE TIMER TEST (FRESH IMPLEMENTATION)
13 November 2026

This release starts from PharmaVault_Streamlined, the version BEFORE the first
timer-demo request. It does not use the cancelled TimerDemo, WiFiFix or
ConnectionFix implementations. It adds a timed variant to the existing IR test.

INSTALL - ESP32 ONLY
1. Extract this ZIP. Open:
   ESP32/PharmaVault_ESP32S3/PharmaVault_ESP32S3.ino
2. Keep your existing ESP32S3 Dev Module, Arduino-ESP32 core 3.x, USB and COM
   settings. No new libraries, wiring or MSP430 upload are needed.
3. Verify and upload normally. Do NOT choose Erase All Flash.
4. Serial Monitor at 115200 baud must show:
   PHARMAVAULT repeat timer test 1
   Send ? to print the saved access details if needed.
5. Join your usual PharmaVault Wi-Fi. Open http://192.168.4.1 and press Ctrl+F5.
   Alternatively use the same-Wi-Fi address printed by the ESP32.
6. Open Test. Look for the new Timer + overdue test panel.

The normal Wi-Fi setup and saved credentials are unchanged from Streamlined.
Its original Save & connect rule is also unchanged: pause the daily schedule
and stop test mode before changing Wi-Fi in Settings. Normal times, pack dates
and existing historical records are retained when uploading without erase.

TEST WITHOUT WAITING FOR THE DAILY TIME
Use an empty carousel or dummy contents. Verified one-compartment stepper
settings are required, just as with the existing IR motor test. The countdown
does not require clock synchronization, a new week, medicine names or an NFC tap.

A. Demonstrate overdue
1. Tick the empty/dummy-contents confirmation in the Test tab.
2. Press Start timer test and accept the confirmation.
3. Keep the hand sensor clear. Starting does NOT move the carousel.
4. At 10 seconds, status becomes TIMER TEST READY.
5. Continue waiting without a hand. At 30 seconds FROM START, TEST OVERDUE
   appears on the dashboard, including the banner above every tab.
6. Keep the sensor clear for at least one second, then hold a hand near it
   continuously for 1.5 seconds. One late test rotation is allowed.
7. The motor turns one configured compartment, then TEST COMPLETE appears.
   This confirms the movement command completed; pill release is not sensed.
8. Present the hand again: no second rotation is allowed in this timer test.

B. Repeat, or demonstrate an on-time completion
1. Wait for the three-second motor cooldown.
2. Tick the empty/dummy confirmation again. Press Restart timer test.
3. The countdown restarts at zero. No date or saved daily time is edited.
4. After the 10-second READY state, clear for one second and hold a hand for
   1.5 seconds. If the rotation finishes before 30 seconds, no overdue alert
   is needed. Restart as often as required.
5. A hand held throughout the initial countdown cannot trigger immediately
   at READY: remove it first, then present a fresh hand.

C. Finish testing
1. Press Stop test mode (also available above every tab).
2. Normal dispensing remains paused. A command already running may finish.
3. Before returning to normal use, sync the real clock if needed, inspect the
   actual day-specific contents, confirm the physical carousel position in
   Settings, then enable the daily schedule. Do not start a new week merely
   because you uploaded or ran a test.

WHAT TESTING CHANGES
- The countdown and test result exist only in RAM; a restart turns tests off.
- Test cycles do not increase daily completed-dose counts, change pack dates,
  reset the seven-day cycle, or edit the saved daily/overdue times.
- As in the original IR test, entering physical tests cancels any already
  pending READY daily dose (marks it FAULT) so it cannot silently resume after
  test movements. Existing overdue records remain; the real calendar continues.
- Test alerts are labelled TEST and are separate from real-day alerts.
- The original repeat-on-every-hand IR test is still available separately.
- Closing the browser does not stop an active test. Use Stop test mode.

The MSP430, NFC, thermistor, DHT11 and GPIO assignments are unchanged.
TEST_CHECKLIST.txt and NORMAL_OPERATION.txt retain the original weekly checks.
WEEKLY_SETUP.txt covers initial weekly pack setup, if needed.

VERIFICATION
See VALIDATION.txt for automated test results and limits. No physical upload
or measurement is claimed. Repeated startup or a literal Brownout message
requires separate diagnosis; this release does not disable power protection.
