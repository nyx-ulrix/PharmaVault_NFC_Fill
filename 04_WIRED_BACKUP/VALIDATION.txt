SCOPE AND LIMITS
Only the ESP32 timed IR test option and its dashboard controls were added.
The cancelled TimerDemo/WiFiFix/ConnectionFix implementations were not reused.
MSP430 files, target-built .out/.hex and wiring match Streamlined byte-for-byte.
No native MSP430 rebuild was needed for this ESP32-only change.

Firmware state-machine tests use the actual assembled .ino compiled with the
host C++ compiler and mocked hardware. Browser-like DOM tests execute the actual
embedded JavaScript, including states emitted by that firmware harness.
These tests do not establish physical motor travel, power stability or RF
connectivity. No live browser/hardware test or upload is claimed.

The installed ESP32 cross-compiler could not launch (Illegal System DLL
Relocation), including a --version probe. Native ESP32 target compilation
therefore remains unverified here; Arduino IDE Verify/upload is required.

No extra large stack buffer was added. Four new small JSON fields reuse the
existing 600-byte test-status buffer. Baseline sendState still declares 4880
bytes of local character arrays; actual compiled stack usage was not measured.
Baseline HTTP handling pauses during motor stepping. Typical 512-step movement
uses roughly 1.54 seconds at the configured 3ms interval; unusually long saved
step counts can exceed the original dashboard request timeout. No connection
rewrite is included in this fresh timer-only implementation.
