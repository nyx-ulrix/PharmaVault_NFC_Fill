PHARMAVAULT WIRELESS TRANSPORT / FIREBEETLE BRIDGE VALIDATION
17 November 2026
Status: PASS (host simulation)

Command: from work/wireless-transport/tests, cmd /c run.cmd
Compiler: Microsoft C++17, /W4 /EHsc; no warnings in the final run.
The test includes the ACTUAL PvWirelessSerial.h, PvTcpChannel.h, PvBridgeCore.h
and ACTUAL PharmaVault_FireBeetle_Bridge.ino. Only Arduino, Wi-Fi/socket,
UART, time and Preferences hardware/OS interfaces are mocked.

PASS: CRC validation, embedded-NUL rejection, overflow resynchronization and
      fragmented line framing.
PASS: wrong/no authentication and protocol frames before authentication rejected.
PASS: fragmented/coalesced receive, corrupt CRC drop, bounded nonblocking
      partial writes, heartbeat and clean reconnection.
PASS: bounded queues and backpressure; three-second frame expiry without replay;
      partial-send expiry closes the stream instead of splicing frames.
PASS: eight-second heartbeat expiry and unsigned millis rollover.
PASS: a TCP frame stalled halfway for three seconds closes the session before
      its remainder can be treated as a fresh frame; UART partial expiry
      discards through the next newline and then recovers.
PASS: actual S3 adapter restricts connections to its AP subnet, rejects a
      second session, and exposes only whole checksum-validated UART frames.
PASS: listener bind failure retries after three seconds without a busy loop or
      restarting an already established listener/session.
PASS: actual FireBeetle UART pins RX16/D11, TX17/D10 at9600 8N1 and USB115200;
      SETUP wizard, strict SSID/password format, persistent pairing/reboot,
      no password echo, offline UART discard, bidirectional protocol roundtrip,
      CANCEL/FORGET behavior and failed Preferences writes.

API compatibility checked against the installed Arduino-ESP32 core3.3.12:
- NetworkServer IPv4-bound constructor, begin(), operator bool(), accept().
- NetworkClient fd(), connected(), setNoDelay(), connect(IP,port,timeoutMs).
- ESP-IDF/lwIP nonblocking socket send/recv using MSG_DONTWAIT.
- Existing HardwareSerial and Preferences APIs retained.
The server does not use NetworkClient::write's potentially blocking retry loop.
The bridge's connect attempt has an explicit100ms timeout, at most once/2s.

LIMITS
These are host tests, not native ESP32 target compilation or RF/hardware tests.
They do not prove USB power, antenna range, radio reconnection timing, actual
UART wiring, measured motor travel or final physical delivery.
The protocol is sent through the password-protected local PharmaVault AP,
with an application handshake using its existing per-device secret. This is
not an internet/TLS service; port4210 is bound to192.168.4.1 only.
