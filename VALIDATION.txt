NATIVE MSP430 BUILD: PASS
TI MSP430 C compiler21.6.2.LTS, MSP430F5529, C99, small code/data model.
main.c, dht11.c and rc522.c compiled and linked without errors/warnings.
The included Firmware .out/.hex were generated from this updated source.
Linker reports RAM1494/8192 bytes and mainFLASH15939/48000 bytes allocated;
interrupt vectors are separately allocated. Physical programming unverified.

ESP32 HOST BUILD/BEHAVIOR: PASS
MSVC C++17 with mocked Arduino/ESP32 peripherals. Existing two-servo,
UART/environment/NFC mapping, ultrasonic and settings tests retained.
New tests verify:
- Complete ordered GPIO3close650ms -> GPIO5position1000ms ->
  GPIO3open650ms -> GPIO3close650ms sequence, no PWM overlap.
- No automatic movement on boot or mode enable; mapped/calibrated slot,
  flap calibration, explicit mode enable and fresh reader state required.
- Fresh CLEAR/EMPTY after mode enable; held card, repeated TAG, retransmitted
  CLEAR/EMPTY and log-only requests cannot repeat a cycle.
- BOOT pauses mode, invalidates reader readiness and resets the retry cache
  so restarted MSP sequence values can be reused in a new session.
- UART acknowledged during motion; busy/cooldown requests rejected; stale
  heartbeat pauses mode; PWM/settings faults prevent further action.
- Accepted manual movement/calibration/tag edits pause automatic mode.
- Independent fill1 calibration, no migration of arbitrary old loaded sample
  to100%; empty/full range and minimum20mm separation, persistence and errors.
- Expected0/25/50/75/100%, rounding, small endpoint clamp, and unavailable
  for missing/unstable/stale/moving/out-of-calibrated-band measurements.

MSP READER/QUEUE BEHAVIOR: PASS
Host fixture extracts real functions from the delivered main.c.
- Held UID produces one presentation; >=1s clean absence produces CLEAR
  followed by EMPTY; a fresh retap produces another presentation.
- RF ambiguity does not declare absence and resets its confirmation timer.
- Different-card replacement queues CLEAR before TAG; queue overflow drops
  the new tap and forces a paused resynchronization rather than late action.
- Unsent TAG expires at500ms, removes its paired LOGREQ, and handles tick
  wrap; already transmitted retries retain their sequence/decision.
- Reader disconnection reports BOOT/pause rather than false removal.

RC522 REGISTER SIMULATION: PASS
Extracts real transceive, rc522_scan and health functions from release.
Clean hardware-timer no-response is distinguished from collision/error,
partial FIFO, partial bits, RX+timer, timeout without hardware IRQ, SPI read
or cleanup failures, SELECT failure and successful UID presentation.
Only clean WUPA silence establishes absence; failures do not re-arm a held tag.

DASHBOARD AND JSON: PASS
JavaScript syntax/mock-DOM tests cover existing manual controls, automatic
mode, fill calibration, percentage rendering, local freshness expiry,
no-echo/movement/connection loss and no motor requests from page/card refresh.
Fifteen actual firmware state snapshots parsed strictly as JSON, including
old range fields plus new NFC/fill fields.

LIMITATIONS
ESP32 native compilation is not claimed. The local native compiler previously
failed to start with Windows Illegal System DLL Relocation; use the user's
working Arduino IDE and ESP32S3 Dev Module settings to compile/upload.
Software simulations do not verify physical servo motion, timing under real
load, power quality, carousel alignment, actual RF behavior, or reliable
ultrasonic reflections from real pills. Browser appearance was not visually
validated in this run. The prototype has no position/gate feedback sensors.
Fill is a current-view height estimate, not pill count or medication delivery.
